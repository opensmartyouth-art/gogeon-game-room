# UX 원칙 (Product & UX Principles)

> 토스의 대표적인 UX 원칙을 정리하고, 실무에서 화면을 설계·리뷰할 때 바로 쓸 수 있도록 적용 가이드와 체크리스트를 덧붙인 문서입니다.

---

## 한눈에 보기

| # | 원칙 | 핵심 질문 |
|---|------|-----------|
| 1 | **One Thing per One Page** | 이 화면이 전달하는 메시지는 하나인가? |
| 2 | **Tap & Scroll** | 탭과 스크롤만으로 플로우를 끝낼 수 있는가? |
| 3 | **Easy to Answer** | 사용자가 3초 안에 답할 수 있는가? |
| 4 | **Value First, Cost Later** | 가치를 먼저 보여주고, 허들은 나중에 요구하는가? |
| 5 | **No Ads Patterns** | 광고처럼 보이는 소구 방식을 쓰고 있지 않은가? |
| 6 | **Context-based** | 사용자의 상황과 흐름에 자연스럽게 이어지는가? |

---

## 1. One Thing per One Page (1페이지 1메시지)

### 정의
하나의 화면에는 오직 하나의 메시지만 담습니다. 불필요한 정보를 과감히 지우고 제외해 인지 부하를 줄입니다.

### 적용 가이드
- 화면을 설계하기 전에 "이 화면의 메시지"를 한 문장으로 먼저 적는다.
- 그 문장에 기여하지 않는 정보·버튼·문구는 삭제하거나 다른 화면으로 분리한다.
- 주요 CTA는 하나만 둔다. 보조 액션이 필요하면 시각적 위계를 명확히 낮춘다.

### Do / Don't
- ✅ 질문 하나 → 답 하나 → 다음 화면
- ❌ 한 화면에 입력 폼, 안내 문구, 프로모션, 부가 옵션을 모두 배치

### 체크리스트
- [ ] 이 화면의 메시지를 한 문장으로 말할 수 있다
- [ ] 주요 CTA가 하나다
- [ ] 지워도 플로우에 지장이 없는 요소가 남아 있지 않다

---

## 2. Tap & Scroll (탭과 스크롤 중심)

### 정의
복잡한 입력 대신, 누르기(`Tap`)와 위아래로 넘기기(`Scroll`)만으로 핵심 플로우를 완결하도록 구성합니다.

### 적용 가이드
- 키보드 입력은 꼭 필요한 경우에만 사용한다.
- 자유 입력 대신 선택지(리스트, 칩, 카드)를 제공한다.
- 좌우 스와이프·롱프레스·드래그처럼 발견하기 어려운 제스처에 핵심 기능을 의존하지 않는다.

### Do / Don't
- ✅ 선택지 리스트에서 탭 한 번으로 선택
- ❌ 직접 타이핑해야 하는 텍스트 필드 여러 개를 연속으로 요구

### 체크리스트
- [ ] 핵심 플로우가 탭과 스크롤만으로 완료된다
- [ ] 키보드 입력이 필요한 단계가 최소화되어 있다
- [ ] 숨겨진 제스처에 의존하는 기능이 없다

---

## 3. Easy to Answer (3초 내 대답)

### 정의
사용자가 마주하는 모든 질문이나 선택에 3초 안에 답할 수 있어야 합니다. 기억하기 힘든 정보는 시스템이 알아서 찾아줍니다.

### 적용 가이드
- 질문은 사용자의 언어로, 하나의 의미만 담아 작성한다.
- 사용자가 기억하거나 찾아봐야 하는 정보(번호, 날짜, 금액 등)는 시스템이 불러오거나 기본값으로 채운다.
- 선택지가 많을 때는 추천값·자주 쓰는 값을 먼저 보여준다.

### Do / Don't
- ✅ "이 계좌로 받을까요?" + 기존 계좌 자동 표시
- ❌ "환급받을 계좌번호를 입력해주세요" + 빈 입력창

### 체크리스트
- [ ] 모든 질문에 3초 안에 답할 수 있다
- [ ] 사용자가 따로 찾아봐야 하는 정보를 요구하지 않는다
- [ ] 전문 용어 없이 이해할 수 있는 문장이다

---

## 4. Value First, Cost Later (가치 우선, 비용 나중)

### 정의
사용자에게 먼저 제품이 주는 혜택과 가치를 체감하게 만든 뒤, 정보 입력이나 비용 지불 같은 허들을 요구합니다.

### 적용 가이드
- 플로우 초반에 사용자가 얻는 결과(혜택, 금액, 추천 결과 등)를 먼저 보여준다.
- 회원가입·본인인증·개인정보 입력·결제는 가치를 체감한 이후로 최대한 뒤로 미룬다.
- 허들을 요구할 때는 "왜 필요한지"를 함께 알려준다.

### Do / Don't
- ✅ 예상 결과를 먼저 보여주고 → 확정을 위해 인증 요청
- ❌ 첫 화면에서 가입·인증부터 요구

### 체크리스트
- [ ] 첫 허들 이전에 사용자가 얻을 가치를 볼 수 있다
- [ ] 정보 입력·비용 요구 시점이 충분히 뒤에 있다
- [ ] 허들마다 요구하는 이유가 설명되어 있다

---

## 5. No Ads Patterns (광고형 패턴 배제)

### 정의
배너 광고 방식의 소구를 지양하고, 기능과 맥락 자체로 사용자가 집중할 수 있게 만듭니다.

### 적용 가이드
- 화려한 배너, 과장된 카피, 깜빡이는 효과 대신 기능 자체로 가치를 전달한다.
- 프로모션이 필요하다면 사용자의 현재 맥락과 연결된 지점에 자연스럽게 녹인다.
- 사용자가 "광고"로 인식해 무시하는 영역(배너 블라인드니스)에 중요한 정보를 두지 않는다.

### Do / Don't
- ✅ 관련 행동을 마친 직후, 이어지는 기능으로 자연스럽게 안내
- ❌ 화면 상단에 맥락과 무관한 프로모션 배너 고정

### 체크리스트
- [ ] 광고 배너처럼 보이는 요소가 없다
- [ ] 과장된 카피나 시각 효과에 의존하지 않는다
- [ ] 안내·추천이 현재 맥락과 연결되어 있다

---

## 6. Context-based (맥락 기반 설계)

### 정의
사용자가 서비스를 이용하는 상황과 흐름을 고려해 자연스럽게 이어지도록 설계합니다.

### 적용 가이드
- 사용자가 "어디서 와서, 무엇을 하려고, 다음엔 어디로 가는지"를 먼저 정의한다.
- 이전 단계에서 얻은 정보는 다음 단계에서 재사용한다.
- 플로우가 끝난 뒤 사용자가 자연스럽게 할 다음 행동을 제시한다.

### Do / Don't
- ✅ 진입 경로에 따라 첫 화면의 메시지·기본값을 다르게 구성
- ❌ 어떤 경로로 들어와도 동일한 화면과 질문을 처음부터 반복

### 체크리스트
- [ ] 진입 맥락(어디서, 왜 왔는지)이 정의되어 있다
- [ ] 이미 받은 정보를 다시 묻지 않는다
- [ ] 완료 이후의 다음 행동이 설계되어 있다

## 디자인 리뷰용 통합 체크리스트

리뷰 시 아래 질문에 모두 "예"라고 답할 수 있는지 확인합니다.

- [ ] **One Thing** — 화면마다 메시지가 하나이고, 주요 CTA가 하나인가?
- [ ] **Tap & Scroll** — 키보드 입력 없이(또는 최소한으로) 플로우가 끝나는가?
- [ ] **Easy to Answer** — 모든 질문에 3초 안에 답할 수 있는가?
- [ ] **Value First** — 허들보다 가치가 먼저 보이는가?
- [ ] **No Ads** — 광고처럼 보이는 요소가 없는가?
- [ ] **Context** — 진입 맥락과 다음 행동이 자연스럽게 이어지는가?

## 고전게임방 적용 기준

> 이 서비스의 주 사용자는 **50대 이상**입니다. 위 여섯 원칙을 게임 화면에 아래처럼 적용하고, 화면을 만들거나 고칠 때마다 이 문서를 먼저 확인합니다.

### 화면 구성
- 게임 화면의 메시지는 하나: **지금 누구 차례이고, 무엇을 하면 되는지**. (One Thing)
- 판(게임 영역)을 가장 크게 둔다. 판 외 정보는 상단 얇은 영역과 하단 고정 바로 한정한다.
- 규칙은 접이식 문단으로 따로 두지 않고 **튜토리얼**(상단 "게임 방법" 버튼, 설정 안 "다시 보기")에 모은다.
- 하단 고정 바에는 주요 동작을 둔다. 게임마다 구성은 달라도 위치·크기는 같다.

### 터치와 글자
- 모든 누르는 대상은 **높이 48px 이상**, 자주 누르는 하단 바 버튼은 **56px 이상**.
- 본문·안내 문구 **16px 이상**, 상태 안내는 **18px 이상**. 숫자와 상태는 굵게.
- 판 위 구슬·돌은 보이는 크기보다 **넓은 판정 영역**을 갖고, 가장 가까운 칸으로 잡는다.
- 끌어서 놓기는 보조 수단이다. 같은 동작을 **탭 두 번(선택 → 도착)**으로도 할 수 있어야 한다. (Tap & Scroll)

### 말투와 용어
- 쉬운 말을 쓴다. 외래어 대신 "게임 목록", "게임 방법".
- 차례는 글자보다 **색·크기·강조**로 보여준다. "차례" 같은 설명 단어는 상태 줄에서 뺀다.
- 접속 상태는 글자 대신 이름 옆 **작은 점**(초록 접속 / 회색 오프라인)으로 보여준다. 접근성용 보이지 않는 설명은 함께 둔다.

### 실수 방지
- 진행 중인 판이 사라지는 동작(새 게임, 게임 목록으로 나가기)은 **한 번 확인**한다. (Easy to Answer: 예/아니오 두 개만)
- 되돌리기는 항상 보이는 위치에 둔다.

### 리뷰 체크리스트 (게임 화면 추가)
- [ ] 판이 화면 폭/높이를 최대한 쓴다 (폰 세로, 높이 664px 기준 스크롤 없음)
- [ ] 누르는 대상이 모두 48px 이상이다 (하단 바는 56px)
- [ ] 글자 크기 기준을 지켰다
- [ ] 드래그 없이 탭만으로도 할 수 있다
- [ ] 차례 표시가 색과 크기만으로 구분된다
- [ ] 진행을 잃는 동작에 확인이 있다
